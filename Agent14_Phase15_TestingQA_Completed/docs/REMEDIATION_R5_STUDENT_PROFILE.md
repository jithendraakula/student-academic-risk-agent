# Remediation R5 — Student Academic Profile

## Goal
Rebuild the authorized-faculty student profile as a scalable academic case-review workspace rather than a collection of loosely grouped cards.

## Product rule
Students are academic records only. This screen is available only to verified Mentor/HOD/Dean authorities according to backend RBAC. There is no student-facing workflow.

## Information hierarchy
1. Student identity and current academic context
2. Current academic status
3. What needs attention now (canonical ML risk signals)
4. Why a different response may be appropriate (faculty context/intent)
5. What is already in progress (active alerts/intervention work items)
6. Course-level failure risk
7. One realistic What-If scenario
8. Mentor AI explanation/recommendation
9. Context history

## Backend additions
`GET /api/predictions/student/{student_id}` now includes `case_management` with active alert work items for the authorized student scope. It deliberately distinguishes operational work items from student counts.

## UI principles
- 8px-style spacing rhythm and bounded content widths.
- Long names/course titles are safely truncated or wrapped.
- Loading, error, empty, success, and in-progress states are explicit.
- Academic risk colors are used only for semantic risk/status information.
- Risk and priority are displayed separately.
- Faculty context is visible beside the numeric evidence it contextualizes.
- What-If is presented as one guided academic scenario, not a dense form dump.
- AI remains a decision-support layer; canonical risk values are not generated by the LLM.
